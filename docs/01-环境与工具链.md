## 1. 三套环境，按需要装

| 用途 | 需要什么 | 何时用 |
|---|---|---|
| **A. 只读探测 / 改键** | Python + `hidapi` | 读键位、备份配置、读电量 |
| **B. 读/写固件** | `wb32-dfu-updater` + WinUSB 驱动 | 备份、刷补丁、救砖 |
| **C. 反编译改固件** | JDK + Ghidra（+ `capstone` 辅助） | 定位要改的地址、生成补丁 |

只做 A 不需要拆机、不改任何东西，是最安全的入口。

## 2. A —— Python 侧

### 2.1 依赖

```bash
py -3.13 -m pip install hidapi capstone
```

| 包 | 用途 | 是否必需 |
|---|---|---|
| `hidapi` | VIA / HID 通信（探测、备份、读电量） | 必需 |
| `capstone` | 反汇编、校验补丁字节 | 只有改固件时需要 |

> 本机约定用 Python 3.13（`py -3.13`）。3.8+ 都能跑，但 3.13 已验证。

### 2.2 确认能连上键盘

前置条件：

```
USB 线连接  +  电源开关拨到 ON  +  按 FN + T 切到「有线 / USB」模式
```

```bash
py -3.13 tools/probe_max102.py      # → temp/max102_info.json
py -3.13 tools/backup_config.py     # → temp/backup_<时间戳>.json
py -3.13 tools/decode_keymap.py     # → tools/keymap_readable.txt
```

期望输出：

```
PROTOCOL_VERSION : 12
FIRMWARE_VERSION : 0.0.0
LAYER_COUNT      : 5
备份 keymap: 5 层 x 6 x 19
MACRO_COUNT      : 16
MACRO_BUF_SIZE   : 1984
```

三个脚本**只发 GET 类命令**，不写 EEPROM、不跳 bootloader，源码可逐行审计。

### 2.3 图形界面（可选）

`web/` 是单文件 WebHID 前端，Chrome / Edge 直接打开 `web/index.html`，
不联网、不依赖 `usevia.app`。见 [web/README.md](../web/README.md)。

## 3. B —— 固件读写工具

### 3.1 下载

| 工具 | 获取 |
|---|---|
| `wb32-dfu-updater_cli` | [GitHub Releases](https://github.com/WestberryTech/wb32-dfu-updater/releases) |
| WinUSB 驱动 | 同一仓库的 `driver/wb_dfu_usb_driver_v1.0.0.0/` |

### 3.2 装 WinUSB 驱动（需要管理员）

驱动**只绑定 `USB\VID_342D&PID_DFA0`**，也就是只在 DFU 模式下有用。

```batch
:: 1. 先让键盘进 DFU（见 04-调试指南.md §2.2）
:: 2. 再装驱动
cd <wb32-dfu-updater>\driver\wb_dfu_usb_driver_v1.0.0.0
dpinst_amd64.exe
```

- 正常模式下**装不了，也不该装**
- 卸载：`dpinst_amd64.exe /u wb_device_in_dfu_mode.inf`

### 3.3 确认能用

```bash
wb32-dfu-updater_cli.exe -l
# Found DFU: [0x342D:0xDFA0] ver=0x0100, devnum=7, cfg=1, intf=0
```

看到这一行就说明工具链通了。接下来立刻做一件事：**备份固件**（见
[04-调试指南.md](04-调试指南.md) §2.4）。

## 4. C —— 反编译环境

### 4.1 组件

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **25+** | Ghidra 12.x 必需，低版本起不来 |
| Ghidra | 12.2 | 反编译主力 |
| `capstone` | 5.0+ | 快速反汇编 / 校验补丁 |

```bash
winget install Microsoft.OpenJDK.25
```

Ghidra 从 [GitHub Releases](https://github.com/NationalSecurityAgency/ghidra/releases) 解压即用。

### 4.2 跑一遍

脚本已经写好，完整参数与坑见 [05-反汇编.md](05-反汇编.md) §8。三步：

1. **导入**固件（`-loader-baseAddr 0x08000000` 不能省）
2. **建符号**（`Max102Post.java`）
3. **导出伪代码**（`ExportDecomp.java`）

产物在 `temp/ghidra_out/`（不进 git）：

| 文件 | 内容 |
|---|---|
| `decompiled_all.c` | 520 个函数的 C 伪代码（458 KB） |
| `functions.asm` | 分组反汇编（516 KB） |
| `functions.txt` | 函数索引 |

## 6. 上手顺序

装完环境后，按这个顺序花一个小时就能建立起整体把握：

1. **备份固件**（10 分钟）—— 最优先，详见 [04-调试指南.md](04-调试指南.md) §2.4
   ```bash
   wb32-dfu-updater_cli.exe -U max102_stock_256k.bin -Z 262144
   ```
   备份完立刻复制到云盘 / U 盘 / 另一台机器。

2. **跑通只读探测**（5 分钟）—— 确认 Python 侧通

3. **读文档**（20 分钟）
   - [03-分析报告.md](03-分析报告.md) §1–§3：结论速览 + 硬件 + 固件备份
   - [06-硬件引脚.md](06-硬件引脚.md)：矩阵 / UART / USB 引脚

4. **打开反编译代码**（随时）
   ```
   VSCode 打开 temp/ghidra_out/decompiled_all.c
   重点看 FUN_08009868（VIA 命令分发器）
   ```

5. **要改固件时** —— 读 [02-改固件流程.md](02-改固件流程.md)

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `probe_max102.py` 找不到设备 | 还在蓝牙模式 / 电源没开 | 按 `FN+T` 切 USB，检查电源开关 |
| 找到了但命令都超时 | 被 `usevia.app` 占用 | 关掉浏览器里打开的 VIA 页面 |
| DFU 工具列不到设备 | 没进 DFU / 驱动没装 | 先按 `FN + 右Shift + ESC`，再装驱动 |
| `analyzeHeadless` 报 JDK 版本 | JDK < 21 | 装 JDK 25，或改 `launch.properties` |
| Ghidra 反编译一堆 `(*(code *)(...))()` | 无函数指针类型信息 | 正常现象，见 [05-反汇编.md](05-反汇编.md) §10 |
